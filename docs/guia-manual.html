📚 Conceptos Clave

Entendé la arquitectura de SAP BTP antes de empezar. Esta sección es fundamental para no perderse en los pasos siguientes.

Arquitectura de un entorno SAP BTP Cloud Foundry Trial completo

Glosario de términos SAP BTP

TérminoQué es
Global AccountEl contenedor raíz de tu entorno SAP BTP. Tiene créditos y servicios globales asignados.
SubaccountDivisión lógica dentro del Global Account. Cada subaccount tiene su propio environment (CF, Kyma, etc.).
Cloud Foundry (CF)El environment de ejecución de apps. Similar a Heroku o Render pero enterprise.
CF OrgAgrupación lógica dentro de CF. En Trial se crea una sola automáticamente.
CF SpaceEntorno de trabajo dentro de una Org. Donde viven los servicios y las apps.
BTP CLICLI para administrar global accounts, subaccounts y entitlements de SAP BTP.
CF CLICLI para gestionar apps, servicios y espacios dentro de Cloud Foundry.
XSUAAExtended Services for User Account and Authentication. Proveedor OAuth2/OIDC de SAP. Maneja la autenticación de las apps.
MTA / mtarMulti-Target Application. El formato de paquete que agrupa todas las partes de una app BTP para deployar.
mta.yamlEl descriptor del MTA. Define módulos (apps), recursos (servicios) y sus relaciones.
AppRouterProxy inverso de SAP. Maneja la autenticación, sesiones y enrutamiento hacia el backend y frontend.
CAPCloud Application Programming model. Framework Node.js de SAP para backends OData/REST.
SAPUI5 / FioriFramework frontend de SAP. Fiori es el sistema de diseño, UI5 es la librería.
BASSAP Business Application Studio. IDE en la nube de SAP (alternativa cloud a VS Code).
MBTMTA Build Tool. Compila el mta.yaml y todos los módulos en un archivo .mtar deployable.
xs-security.jsonConfiguración del scope de XSUAA: roles, scopes y cómo se autentica la app.
html5-apps-repoServicio de hosting de contenido estático (UI5/React) en BTP. Tiene dos planes: app-host y app-runtime.
EntitlementEl permiso para usar un servicio en tu subaccount. En Trial vienen preconfigurados.
💡
Flujo general resumido Global Account → Subaccount → Activar CF Environment → Crear Space → Crear Servicios → Desarrollar App → Build con MBT → Deploy con CF CLI → Verificar

🚀 Pasos de Configuración

Seguí cada paso en orden. Cada uno tiene una estimación de tiempo y clasificación: Manual (requiere el Cockpit web), Semi-manual (CLI con pasos en browser), CLI (todo por terminal).

1

Crear cuenta SAP BTP Trial

Registro gratuito en account.hanatrial.ondemand.com · ~15 min

🖱 Manual · Cockpit ▾
✅
La cuenta Trial de SAP BTP es completamente gratuita y no requiere tarjeta de crédito. Dura 90 días y se puede renovar.
1
Ir al portal de registro

Abrí https://account.hanatrial.ondemand.com/ en tu browser.

2
Crear cuenta SAP Universal ID

Hacé clic en "Log On" y luego en "Register". Completá el formulario con email, nombre y contraseña. Vas a recibir un email de verificación — confirmalo antes de continuar.

Link directo al registro: https://account.hanatrial.ondemand.com/register

3
Seleccionar región del Trial

Después del login, el wizard de SAP te va a pedir elegir una región. Las más comunes son:

RegiónCódigoRecomendada para
Europe (Frankfurt)eu10Europa y Latinoamérica ✅
US East (VA)us10Norteamérica
Singaporeap21Asia-Pacífico
⚠️
Una vez elegida la región no se puede cambiar. Elegí eu10 si no tenés preferencia específica.
4
Acceder al Cockpit

Después del wizard llegás al SAP BTP Cockpit. Tu URL va a ser similar a:

https://cockpit.eu10.hana.ondemand.com/cockpit/#/globalaccount/XXXXXXXX/subaccount/YYYYYYYY

Guardá esta URL — es tu punto de entrada al dashboard de administración.

📌
Datos que necesitás guardar después de este paso: tu email de SAP, la región elegida (ej: eu10), y el subdomain de tu global account (visible en el Cockpit).
2

Activar Cloud Foundry Environment

Habilitar CF en tu subaccount Trial · ~10 min

🖱 Manual · Cockpit ▾
1
Ir a tu Subaccount

En el Cockpit, hacé clic en "trial" en la lista de subaccounts. Este es el subaccount Trial preconfigurado por SAP.

2
Ir a Cloud Foundry Environment

En el menú izquierdo → Cloud Foundry → Spaces. Si no está activado, vas a ver un botón "Enable Cloud Foundry".

3
Habilitar CF

Hacé clic en "Enable Cloud Foundry". Dejá los valores por defecto:

  • Plan: standard
  • Org name: se asigna automáticamente (ej: trial12345trial)

Hacé clic en "Create". Espera 1-2 minutos a que finalice.

4
Anotar el API Endpoint de CF

Una vez habilitado, vas a ver el API Endpoint. Tiene el formato:

https://api.cf.eu10.hana.ondemand.com

Guardalo — lo vas a necesitar para hacer login con CF CLI.

5
Crear el CF Space

Hacé clic en "Create Space". Nombre sugerido: dev. Dejá los roles por defecto y confirmá.

💡
También podés crear el Space desde CLI en el Paso 5. Hacerlo desde el Cockpit es más simple para el primer setup.
3

⚠️

Si cf version devuelve 7.x: Tenés CF CLI v7 instalado. Desinstalalo completamente y seguí las instrucciones del Paso 3 para instalar v8. Los dos no conviven sin problemas.
4

Login BTP CLI y CF CLI

Autenticación en SAP BTP y Cloud Foundry · ~10 min

⚠ Semi-manual · SSO ▾
⚠️
SAP usa autenticación OIDC con browser. No es posible hacer login headless con usuario/contraseña directo en terminal. En Trial esto se maneja con one-time passcodes que duran 60 segundos — tené el browser a mano.

Login BTP CLI

# Login en el Global Account de SAP BTP # Reemplazá REGION por tu región: eu10, us10, ap21, etc. btp login --url https://cli.btp.cloud.sap --idp sap.default # Se abre el browser para completar el login OIDC # Usá tu email y contraseña de SAP Universal ID # Verificar login btp list accounts/subaccount
💡
URL de BTP CLI por región
RegiónURL BTP CLI
eu10 (Frankfurt)https://cli.btp.cloud.sap
us10 (Virginia)https://cli.btp.cloud.sap
Todas las regioneshttps://cli.btp.cloud.sap (global)

Seleccionar Subaccount activo en BTP CLI

# Listar subaccounts disponibles btp list accounts/subaccount # Seleccionar el subaccount Trial btp target --subaccount SUBACCOUNT_GUID # El GUID aparece en la columna "id" del comando anterior # También lo podés ver en el Cockpit: URL del browser cuando estás en el subaccount

Login CF CLI

# Login con SSO (recomendado para Trial) # Reemplazá la URL con tu API Endpoint de CF (lo anotaste en el Paso 2) cf login -a https://api.cf.eu10.hana.ondemand.com --sso # El comando va a mostrarte una URL temporal, por ejemplo: # One Time Code ( Get one at https://login.cf.eu10.hana.ondemand.com/passcode ) # 1. Abrí esa URL en el browser # 2. Logueate con tu cuenta SAP # 3. Copiá el código de 6 caracteres que aparece # 4. Pegalo en la terminal (tenés 60 segundos) # Seleccionar Org y Space cuando te lo pida
⏱️
El one-time passcode expira en 60 segundos. Si tardás, el login falla con "Invalid passcode". Simplemente corré cf login --sso de nuevo para obtener un código nuevo.

Verificar login CF

# Ver la sesión activa cf target # Salida esperada: # API endpoint: https://api.cf.eu10.hana.ondemand.com # API version: 3.x.x # user: tu@email.com # org: trialXXXXXXXXXtrial # space: dev
5

Crear CF Space (si no lo hiciste en el Cockpit)

Espacio de trabajo donde van los servicios y las apps · ~5 min

💻 CLI ▾
💡
Si ya creaste el Space "dev" desde el Cockpit en el Paso 2, podés saltarte este paso. Solo verificá con cf spaces.
# Listar spaces existentes cf spaces # Crear space "dev" si no existe cf create-space dev # Apuntar a ese space cf target -s dev # Verificar cf target
6

Crear instancias de servicios CF

xsuaa, destination, html5-apps-repo × 2, application-logs · ~20 min

💻 CLI ▾
ℹ️
Los servicios se crean de forma asincrónica. Después de cada cf create-service podés verificar el estado con cf services. Esperá a que el status sea "create succeeded" antes de continuar.

Verificar catálogo de servicios disponibles

# Ver todos los servicios disponibles en tu espacio cf marketplace # Filtrar por un servicio específico cf marketplace -e xsuaa cf marketplace -e html5-apps-repo

1. Servicio XSUAA (autenticación OAuth2)

# Crear instancia XSUAA # Nombre del servicio: xsuaa # Plan: application # Nombre de la instancia: my-app-xsuaa cf create-service xsuaa application my-app-xsuaa -c xs-security.json # NOTA: xs-security.json debe existir antes de este comando # Ver Paso 9 de la sección Proyecto para generarlo # Si querés crear el servicio sin config inicial (para ajustar después): cf create-service xsuaa application my-app-xsuaa

2. Servicio Destination (conectividad externa)

# Plan: lite (gratuito en Trial) cf create-service destination lite my-app-destination

3. HTML5 App Repository — app-host (subir estáticos)

# Plan: app-host — para subir el contenido estático (HTML, JS, CSS de UI5) cf create-service html5-apps-repo app-host my-app-html5-host

4. HTML5 App Repository — app-runtime (AppRouter)

# Plan: app-runtime — credenciales OAuth que usa el AppRouter en runtime # ⚠ CRÍTICO: el AppRouter DEBE estar bindeado a app-runtime, NO a app-host # Bindear el AppRouter a app-host genera el error "grant_type: missing" cf create-service html5-apps-repo app-runtime my-app-html5-runtime

5. Application Logging (logs centralizados)

# Plan: lite cf create-service application-logs lite my-app-logs

Verificar todos los servicios

# Ver estado de todos los servicios del space cf services # Salida esperada (todos en "create succeeded"): # name service plan bound apps last operation # my-app-xsuaa xsuaa application create succeeded # my-app-destination destination lite create succeeded # my-app-html5-host html5-apps-repo app-host create succeeded # my-app-html5-runtime html5-apps-repo app-runtime create succeeded # my-app-logs application-logs lite create succeeded
⏳
Algunos servicios tardan hasta 5 minutos en crearse. Si el status es "create in progress", esperá y repetí cf services hasta que todos digan "create succeeded".
7

Suscribir SAP BAS y asignar roles

IDE en la nube de SAP — limitación del Trial, solo desde Cockpit · ~15 min

🖱 Manual · Cockpit ▾
🚨
Limitación de SAP Trial: BAS no se puede suscribir por API ni CLI. Es obligatorio hacerlo desde el Cockpit web. No existe ninguna alternativa automatizable para este paso.
1
Ir a Service Marketplace en el Cockpit

En tu Subaccount Trial → menú izquierdo → Services → Service Marketplace

2
Buscar SAP Business Application Studio

En el buscador escribí "Business Application Studio". Hacé clic en la card del servicio.

3
Crear suscripción

Hacé clic en "Create". En el modal:

  • Service: SAP Business Application Studio
  • Plan: free (Trial)

Confirmá con "Create". La suscripción tarda 2-5 minutos.

4
Asignar Role Collection al usuario

Sin este rol, BAS va a dar un error de acceso aunque esté suscripto.

  • Menú izquierdo → Security → Role Collections
  • Buscá "Business_Application_Studio_Developer"
  • Hacé clic en el rol → Edit → pestaña Users
  • Agregá tu email de SAP → Save
5
Acceder a BAS

Menú izquierdo → Instances and Subscriptions → SAP Business Application Studio → Go to Application

URL directa: https://[subdomain].eu10cf.applicationstudio.cloud.sap/index.html

💡
BAS es opcional si vas a desarrollar localmente con VS Code. Solo es necesario si preferís el IDE de SAP en el browser.

🏗️ Estructura del Proyecto

Creación manual de un proyecto CAP + SAPUI5 + AppRouter desde cero. Incluye xs-security.json y mta.yaml completos.

8

Crear estructura del proyecto

Scaffold CAP + SAPUI5 + AppRouter · ~30 min

💻 CLI ▾

Estructura de carpetas objetivo

my-btp-app/ ├── approuter/ ← AppRouter Node.js │ ├── package.json │ └── xs-app.json ← Reglas de routing del AppRouter ├── app/ │ └── my-btp-app/ ← App SAPUI5 / Fiori │ ├── webapp/ │ │ ├── manifest.json │ │ ├── Component.js │ │ └── index.html │ ├── ui5.yaml │ └── package.json ├── srv/ ← Backend CAP (OData / REST) │ ├── cat-service.cds │ ├── cat-service.js │ └── package.json ├── db/ ← Schema de base de datos CDS │ └── schema.cds ├── xs-security.json ← Config XSUAA ├── mta.yaml ← Descriptor MTA (build + deploy) └── package.json ← Root package.json

1. Inicializar el proyecto CAP

# Crear directorio del proyecto mkdir my-btp-app cd my-btp-app # Inicializar proyecto CAP cds init # Agrega: package.json, .gitignore, README.md, carpetas srv/, db/, app/ # Verificar estructura generada ls -la

2. Agregar módulo de base de datos (schema)

Editá db/schema.cds:

// db/schema.cds namespace my.btpapp; entity Products { key ID : UUID; name : String(100) @mandatory; descr : String(500); price : Decimal(10,2); currency : String(3); createdAt : Timestamp @cds.on.insert: $now; modifiedAt: Timestamp @cds.on.update: $now; }

3. Definir el servicio CAP

Editá srv/cat-service.cds:

// srv/cat-service.cds using my.btpapp from '../db/schema'; service CatalogService @(path:'/catalog') { entity Products as projection on btpapp.Products; annotate Products with @odata.draft.enabled; }

4. Instalar dependencias SAP en el proyecto

# En la raíz del proyecto npm install # Agregar soporte BTP (XSUAA + logging) npm install @sap/xssec @sap/audit-logging # Agregar passport para integración XSUAA npm install passport # En el directorio srv/ cd srv && npm init -y npm install @sap/cds @sap/xssec passport cd ..

5. Crear el AppRouter

# Crear directorio del AppRouter mkdir approuter cd approuter npm init -y npm install @sap/approuter cd ..

Crear approuter/xs-app.json:

{ "welcomeFile": "/index.html", "authenticationMethod": "route", "routes": [ { "source": "^/catalog/(.*)$", "target": "/catalog/$1", "destination": "srv-api", "authenticationType": "xsuaa", "csrfProtection": true }, { "source": "^(.*)$", "target": "$1", "service": "html5-apps-repo-rt", "authenticationType": "xsuaa" } ] }

Crear approuter/package.json:

{ "name": "my-btp-app-approuter", "version": "1.0.0", "scripts": { "start": "node node_modules/@sap/approuter/approuter.js" }, "dependencies": { "@sap/approuter": "^14.0.0" } }

6. Crear la app SAPUI5

# Desde la raíz del proyecto mkdir -p app/my-btp-app/webapp cd app/my-btp-app # Inicializar proyecto UI5 npm init -y npm install --save-dev @ui5/cli @openui5/sap.ui.core

Crear app/my-btp-app/webapp/manifest.json:

{ "_version": "1.65.0", "sap.app": { "id": "my.btpapp", "type": "application", "i18n": "i18n/i18n.properties", "applicationVersion": { "version": "1.0.0" }, "title": "{{appTitle}}", "description": "{{appDescription}}", "dataSources": { "mainService": { "uri": "/catalog/", "type": "OData", "settings": { "odataVersion": "4.0" } } } }, "sap.ui": { "technology": "UI5", "icons": { "icon": "" }, "deviceTypes": { "desktop": true, "tablet": true, "phone": true } }, "sap.ui5": { "rootView": { "viewName": "my.btpapp.view.App", "type": "XML", "async": true, "id": "app" }, "models": { "": { "dataSource": "mainService", "settings": { "synchronizationMode": "None", "operationMode": "Server" } } } } }

Crear app/my-btp-app/ui5.yaml:

specVersion: "3.0" metadata: name: my-btp-app type: application framework: name: SAPUI5 version: "1.120.0" libraries: - name: sap.m - name: sap.ui.core - name: sap.ushell builder: resources: excludes: - "/test/**" - "/localService/**"
9

Configurar xs-security.json

Definición de OAuth2 scopes y roles para XSUAA · ~10 min

💻 CLI ▾

El archivo xs-security.json se crea en la raíz del proyecto y define cómo se autentica y autoriza la app vía XSUAA.

xs-security.json base

{ "xsappname": "my-btp-app", "tenant-mode": "dedicated", "description": "My BTP Application Security Descriptor", "scopes": [ { "name": "$XSAPPNAME.read", "description": "Read access to catalog data" }, { "name": "$XSAPPNAME.write", "description": "Write access to catalog data" } ], "attributes": [], "role-templates": [ { "name": "Viewer", "description": "Can view catalog data", "scope-references": ["$XSAPPNAME.read"] }, { "name": "Editor", "description": "Can view and edit catalog data", "scope-references": ["$XSAPPNAME.read", "$XSAPPNAME.write"] } ], "role-collections": [ { "name": "my-btp-app-viewer", "description": "Viewer Role Collection", "role-template-references": ["$XSAPPNAME.Viewer"] }, { "name": "my-btp-app-editor", "description": "Editor Role Collection", "role-template-references": ["$XSAPPNAME.Editor"] } ], "oauth2-configuration": { "redirect-uris": ["https://*.hana.ondemand.com/**"] } }
💡
El valor "tenant-mode": "dedicated" es correcto para Trial (un solo tenant). En escenarios multi-tenant se usa "shared".

Actualizar el servicio XSUAA con este archivo

# Si el servicio ya existe, actualizarlo con el nuevo xs-security.json: cf update-service my-app-xsuaa -c xs-security.json # Si todavía no lo creaste: cf create-service xsuaa application my-app-xsuaa -c xs-security.json
10

Configurar mta.yaml

Descriptor Multi-Target Application — el corazón del deploy · ~20 min

💻 Configuración ▾
⚠️
El mta.yaml es el archivo más crítico del deploy. Los errores más comunes son: AppRouter bindeado a app-host en lugar de app-runtime, uso de npm ci en lugar de npm install, y dependencias circulares con deployed-after.

Creá el archivo mta.yaml en la raíz del proyecto:

_schema-version: '3.1' ID: my-btp-app version: 1.0.0 description: "SAP BTP App — CAP + SAPUI5 + AppRouter" parameters: enable-parallel-deployments: true build-parameters: before-all: - builder: custom commands: - npm install --prefix app/my-btp-app modules: # ─── 1. AppRouter ─────────────────────────────────────────────── - name: my-btp-app-approuter type: approuter.nodejs path: approuter/ parameters: keep-existing-routes: true disk-quota: 256M memory: 256M requires: - name: my-app-xsuaa - name: my-app-destination # ⚠ IMPORTANTE: app-runtime, NO app-host - name: my-app-html5-runtime - name: srv-api group: destinations properties: forwardAuthToken: true strictSSL: false name: srv-api url: "~{srv-url}" build-parameters: builder: npm # ⚠ IMPORTANTE: usar npm install, NO npm-ci build-result: "." ignore: - "node_modules/" - "default-env.json" # ─── 2. UI Deployer (sube el contenido estático a html5-apps-repo) ─── - name: my-btp-app-ui-deployer type: com.sap.application.content path: app/my-btp-app requires: - name: my-app-html5-host parameters: content-target: true build-parameters: build-result: dist builder: custom commands: - npm install - npm run build supported-platforms: [] # ─── 3. CAP Backend (srv) ─────────────────────────────────────── - name: my-btp-app-srv type: nodejs path: srv/ parameters: buildpack: nodejs_buildpack disk-quota: 512M memory: 256M properties: EXIT: 1 requires: - name: my-app-xsuaa - name: my-app-logs provides: - name: srv-api properties: srv-url: ${default-url} build-parameters: builder: npm build-result: "." ignore: - "node_modules/" resources: # ─── XSUAA ─────────────────────────────────────────────────────── - name: my-app-xsuaa type: org.cloudfoundry.managed-service parameters: service: xsuaa service-plan: application path: ./xs-security.json config: xsappname: my-btp-app-${org}-${space} tenant-mode: dedicated # ─── Destination ───────────────────────────────────────────────── - name: my-app-destination type: org.cloudfoundry.managed-service parameters: service: destination service-plan: lite # ─── HTML5 App Host (contenido estático) ───────────────────────── - name: my-app-html5-host type: org.cloudfoundry.managed-service parameters: service: html5-apps-repo service-plan: app-host # ─── HTML5 App Runtime (AppRouter OAuth) ───────────────────────── - name: my-app-html5-runtime type: org.cloudfoundry.managed-service parameters: service: html5-apps-repo service-plan: app-runtime # ─── Application Logs ──────────────────────────────────────────── - name: my-app-logs type: org.cloudfoundry.managed-service parameters: service: application-logs service-plan: lite
✅
4 errores críticos que este mta.yaml ya tiene resueltos:
  • AppRouter bindeado a app-runtime (no app-host) → evita "grant_type: missing"
  • Usa npm install (no npm ci) → evita fallas en el build
  • No incluye módulo xsuaa-deployer → evita conflictos en proyectos simples
  • No usa deployed-after → evita dependencias circulares

Build con MBT

Compilar mta.yaml → archivo .mtar deployable · ~10 min

💻 CLI ▾
# Desde la raíz del proyecto (donde está mta.yaml) cd my-btp-app # Build del MTA mbt build # El comando genera: # mta_archives/my-btp-app_1.0.0.mtar # Si querés más detalle del proceso: mbt build --mtar my-btp-app.mtar # Verificar que el .mtar se generó ls mta_archives/
💡
El build corre npm install y npm run build en cada módulo. Si alguno falla, corré manualmente npm install en ese directorio y luego reintentá el build.

Deploy en Cloud Foundry

Subir el .mtar a CF y verificar que las apps levanten · ~15 min

💻 CLI ▾
# Verificar que estás logueado y apuntando al space correcto cf target # Deploy del .mtar cf deploy mta_archives/my-btp-app_1.0.0.mtar # Con output más detallado: cf deploy mta_archives/my-btp-app_1.0.0.mtar --retries 1 # El proceso puede tardar 5-15 minutos # Vas a ver el progreso de cada módulo: # Uploading 1 files... # Processing: Deploying... # Application: my-btp-app-approuter started # Application: my-btp-app-srv started

Verificar estado post-deploy

# Ver todas las apps del space cf apps # Salida esperada (todas en "started"): # name requested state instances # my-btp-app-approuter started 1/1 # my-btp-app-srv started 1/1 # Ver URL de la app cf app my-btp-app-approuter # La URL de acceso aparece en la línea "routes:" # Ejemplo: my-btp-app-approuter.cfapps.eu10.hana.ondemand.com

Ver logs en tiempo real

# Logs recientes (útil para debuggear crashes) cf logs my-btp-app-approuter --recent # Logs en tiempo real (streaming) cf logs my-btp-app-approuter # Logs del backend CAP cf logs my-btp-app-srv --recent
🎉
¡Deploy exitoso! Abrí la URL del AppRouter en el browser. Deberías ver el login de SAP y, luego de autenticarte, tu app SAPUI5.

Comandos útiles post-deploy

# Reiniciar una app cf restart my-btp-app-approuter # Ver variables de entorno de una app cf env my-btp-app-approuter # Ver los servicios bindeados a una app cf services # Escalar instancias cf scale my-btp-app-approuter -i 2 # Detener app (para ahorrar quota en Trial) cf stop my-btp-app-approuter cf stop my-btp-app-srv # Eliminar el MTA completo cf undeploy my-btp-app --delete-services

🔧 Troubleshooting

Los errores más frecuentes en cada etapa del setup manual, con causa raíz y solución exacta. Hacé clic en cada error para ver la solución.

🔐 Errores de Login y Autenticación

One Time Code has expired or invalid
Causa: El passcode SSO de CF dura 60 segundos. Si tardás en pegarlo, expira.

Solución: Corré cf login -a [API-ENDPOINT] --sso nuevamente. La URL del browser te genera un código nuevo. Tenelo listo antes de correr el comando.
FAILED: Not logged in. Use 'cf login' or 'cf api'
Causa: La sesión de CF expiró (suele pasar después de varias horas).

Solución: cf login -a https://api.cf.eu10.hana.ondemand.com --sso
btp: command not found / cf: command not found
Causa: La herramienta no está en el PATH del sistema, o el terminal no se reinició después de instalarla.

Solución: Cerrá y volvé a abrir el terminal. En Windows, abrí una terminal nueva como Administrador. Verificá con where btp (Windows) o which btp (Mac/Linux).

⚙️ Errores de Servicios CF

Service broker returned error: quota exceeded
Causa: Llegaste al límite de instancias de servicios en Trial (generalmente 10 instancias en total).

Solución: Eliminá servicios que no uses: cf delete-service NOMBRE-SERVICIO. Podés ver todos con cf services.
Service 'html5-apps-repo' not found en cf marketplace
Causa: El entitlement del servicio no está asignado al subaccount.

Solución: En el Cockpit → Subaccount → Entitlements → Edit → Buscá "HTML5 Application Repository" → Asigná los planes app-host y app-runtime → Save.
Service instance status: create failed
Causa: El JSON de configuración tiene un error de sintaxis, o el plan no está disponible.

Solución: cf service my-app-xsuaa para ver el mensaje de error detallado. Eliminá la instancia con cf delete-service my-app-xsuaa y volvé a crearla.

🏗️ Errores de Build (mbt)

Build error: command 'npm ci' exited with code 1
Causa: MBT intenta usar npm ci que requiere un package-lock.json exacto que puede no existir o estar desactualizado.

Solución: En el mta.yaml, en el bloque build-parameters de cada módulo, cambiá el builder de npm-ci a npm.
Cannot find module '@sap/approuter'
Causa: Las dependencias del AppRouter no están instaladas localmente.

Solución: cd approuter && npm install && cd ... Luego reintentá mbt build.
YAML parse error: found duplicate key
Causa: El mta.yaml tiene una clave duplicada o indentación incorrecta.

Solución: Pegá el contenido del mta.yaml en yamlchecker.com para validarlo. YAML usa 2 espacios de indentación, nunca tabs.

☁️ Errores de Deploy (cf deploy)

grant_type: missing field — AppRouter crashea
Causa: El AppRouter está bindeado al plan app-host del HTML5 App Repository. Este plan no provee credenciales OAuth. El AppRouter necesita app-runtime.

Solución: En el mta.yaml, en el módulo del AppRouter, en la sección requires, reemplazá la referencia a app-host por una a app-runtime. Creá una instancia del plan app-runtime si no existe.
Application crashed immediately after start
Causa: Error en el código de la app, variable de entorno faltante, o binding mal configurado.

Solución: cf logs my-btp-app-approuter --recent — buscá la línea del error real. Revisá también cf env my-btp-app-approuter para confirmar que los servicios están bindeados.
Deployment failed: circular dependency detected
Causa: El mta.yaml usa la propiedad deployed-after que puede crear dependencias circulares entre módulos.

Solución: Eliminá todas las apariciones de deployed-after del mta.yaml. En su lugar, usá requires para expresar dependencias.
Error: Memory limit exceeded (Trial quota)
Causa: El Trial tiene 2GB de RAM total. Si tenés muchas apps corriendo, la memoria se agota.

Solución: cf stop las apps que no uses. Reducí la memoria en mta.yaml (memory: 128M para el srv y memory: 128M para el approuter).
403 Forbidden al acceder a la URL del AppRouter
Causa: El usuario no tiene la Role Collection asignada en el Cockpit.

Solución: Cockpit → Security → Role Collections → Buscá la role collection de tu app → Edit → Users → Agregá tu email → Save. Hacé logout del browser y volvé a entrar.

🔑 Errores de XSUAA

Illegal state: xsappname already taken
Causa: Ya existe una instancia XSUAA con el mismo xsappname en el espacio.

Solución: Cambiá el xsappname en el xs-security.json (ej: my-btp-app-v2) o eliminá la instancia existente con cf delete-service my-app-xsuaa.
INVALID_REQUEST: redirect_uri not allowed
Causa: La URL de la app no está en la lista de redirect-uris del xs-security.json.

Solución: Actualizá el xs-security.json para incluir la URL real de tu app: "redirect-uris": ["https://*.hana.ondemand.com/**", "https://tu-app-url/**"] y luego corré cf update-service my-app-xsuaa -c xs-security.json.
