¿Qué es BTP Starter Pack?

Una aplicación web con wizard paso a paso que guía a cualquier desarrollador o consultor SAP a través de la configuración de un entorno SAP BTP Cloud Foundry — y genera proyectos full-stack estructurados, con mejores prácticas aplicadas y listos para evolucionar hacia producción.

📐 Honestidad ante todo La herramienta entrega una base sólida y funcional. El camino hacia producción real depende de requisitos de negocio, seguridad y arquitectura propios de cada cliente — la herramienta elimina el trabajo inicial más tedioso y propenso a errores.

Quick Start — De cero a running en 5 minutos

Requisito previo: tener Node.js 18+ instalado.

1. Clonar e instalar

# Clonar el repositorio
$ git clone https://github.com/juanignaciopalom-lgtm/btp-starter-pack.git
$ cd btp-starter-pack

# Instalar dependencias
$ npm install

# Compilar TypeScript → JavaScript
$ npm run build

# Compilar también el frontend React
$ npm run build:ui

2. Iniciar el servidor y abrir el wizard

# Iniciar servidor + abrir UI automáticamente en el browser
$ node dist/index.js ui

# O con npm:
$ npm run start:ui
✅ El wizard se abre en tu browser El servidor escucha en http://localhost:3001 — la UI se abre automáticamente.

3. Seguir los 6 pasos del wizard

La interfaz te guía paso a paso. Cada paso tiene un botón de acción, estado visual y mensajes de error claros.

Paso 6 — Deploy: Build y Deploy a Cloud Foundry
Automático

Compila el MTA archive y lo despliega a tu CF Space.

Troubleshooting por Paso

Errores posibles en cada uno de los 6 pasos del wizard. Hacé clic en cada problema para ver la solución.

🩺 Paso 1 — Doctor

❌ command not found para Node, Git, CF CLI, BTP CLI, CDS, UI5 o MBT ▼

La herramienta está instalada pero no está en el PATH del sistema, o no está instalada.

# Verificar:
$ node --version
$ cf --version
$ btp --version

# En Windows, después de instalar: cerrar y reabrir la terminal
# Los cambios de PATH no se aplican a terminales ya abiertas

# CF CLI — Mac:
$ brew install cloudfoundry/tap/cf-cli@8
# Windows: Descargar installer de GitHub y reiniciar terminal

# MBT, CDS, UI5:
$ npm install -g mbt @sap/cds-dk @ui5/cli
❌ CF CLI detectado como v7 pero se requiere v8 ▼

SAP BTP requiere CF CLI v8. La v7 tiene diferencias de API que pueden causar errores.

# Verificar versión:
$ cf --version
# Si dice cf version 7.x.x, actualizá

# Mac:
$ brew upgrade cf-cli@8
# Windows: Desinstalar v7 desde Panel de Control, descargar v8 de GitHub
❌ Doctor pasa pero luego falla en otro paso ▼

Puede ser que el PATH del terminal donde corrés el wizard sea diferente al de tu sesión. Reiniciá la terminal o usá el wizard recién después de reiniciar.

⚠ Windows específico: Si instalaste herramientas con winget o un installer, siempre cerrá y reabrí PowerShell/CMD/Windows Terminal antes de correr el wizard.

🔐 Paso 2 — BTP Login

❌ El browser no se abre automáticamente ▼

En algunos entornos corporativos o WSL, el comando open no funciona. El wizard imprime la URL en la consola.

# Copiá la URL del output del wizard y abrila manualmente en tu browser
# Ejemplo de URL:
https://cpcli.cf.eu10.hana.ondemand.com
❌ Error: "Global Account Subdomain inválido" o "subaccount not found" ▼

El subdomain de tu Global Account BTP es diferente al que ingresaste. Para encontrarlo:

  1. Abrir BTP Cockpit
  2. Click en tu Global Account (Trial)
  3. En la URL del browser: https://account.hanatrial.ondemand.com/cockpit#/globalaccount/TU-SUBDOMAIN
  4. O en la vista de cuenta → sección "Global Account Information" → campo "Subdomain"
❌ Error de autenticación OIDC / timeout en el browser ▼

El flujo OIDC tiene un timeout. Si tardás en completar el login en el browser, la sesión expira.

  • Hacé clic en "Reset BTP Login" en el wizard para reintentar
  • Completá el login en el browser antes de cambiar de pestaña
  • Si usás MFA/2FA, tenelo activo antes de empezar
❌ BTP CLI sesión expirada en pasos posteriores ▼

Las sesiones de BTP CLI expiran (generalmente en horas). Si corrés el wizard en varios días, necesitás re-loguearte.

# Verificar si la sesión está activa:
$ btp target
# Si falla → usá "Reset BTP Login" en el wizard

☁️ Paso 3 — CF Login

❌ One-Time Passcode expirado (SSO timeout) ▼

El código SSO de Cloud Foundry expira en ~60 segundos. Si tardás en copiarlo y pegarlo, tenés que generar uno nuevo.

⚠ Tip crítico: Tenés el browser abierto y listo antes de hacer clic en "CF Login". Así copiás el código apenas aparece.

Usá el botón "Reset CF Login" en el wizard para reintentar.

❌ CF API endpoint incorrecto / "API endpoint not found" ▼

El endpoint de CF depende de tu región BTP. Si tu subaccount está en eu10 y usás el endpoint de us10, va a fallar.

# Para encontrar tu endpoint correcto:
# BTP Cockpit → tu Subaccount → Cloud Foundry → API Endpoint

# eu10: https://api.cf.eu10.hana.ondemand.com
# us10: https://api.cf.us10.hana.ondemand.com
❌ cf target no muestra org/space después del login ▼ 
# Setear manualmente el target:
$ cf target -o "NombreDeOrg" -s "dev"

# Listar orgs disponibles:
$ cf orgs

# Listar spaces:
$ cf spaces
❌ Error SSL / proxy corporativo bloquea CF API ▼

En redes corporativas, el proxy o firewall puede bloquear las conexiones a SAP CF.

  • Verificar con tu equipo de IT si *.hana.ondemand.com está permitido
  • Configurar proxy en CF CLI: export https_proxy=http://proxy:port
  • Para certificados SSL corporativos: cf api --skip-ssl-validation (solo para debugging, no producción)

⚙️ Paso 4 — Setup (Crear Servicios CF)

❌ "Service plan not found" / servicio no disponible en la región ▼

No todos los servicios SAP BTP están disponibles en todas las regiones. Esto es especialmente común en Trial.

# Ver qué servicios están disponibles en tu región:
$ cf marketplace

# Filtrar por nombre:
$ cf marketplace | grep xsuaa
$ cf marketplace | grep html5
⚠ Si un servicio no aparece en cf marketplace: No es posible crearlo en esa región. Puede requerirse habilitarlo desde BTP Cockpit → Entitlements.
❌ Quota excedida en Trial / "Not enough resources" ▼

SAP BTP Trial tiene límites de recursos. Si creaste servicios en intentos anteriores, pueden estar consumiendo quota.

# Ver todos los servicios existentes:
$ cf services

# Eliminar servicios que ya no necesitás:
$ cf delete-service nombre-del-servicio

# Ver apps consumiendo recursos:
$ cf apps
❌ "Instance with same name already exists" ▼

El setup anterior dejó instancias de servicio con el mismo nombre.

# Listar servicios:
$ cf services

# Si el servicio existe y está bien, el setup puede saltearlo
# Si está en error, eliminarlo y recrear:
$ cf delete-service nombre-existente
# Luego retomar el setup desde el wizard
❌ Servicio queda en estado "create in progress" por mucho tiempo ▼

Algunos servicios tardan varios minutos en crearse. Es normal para xsuaa y html5-apps-repo.

# Verificar estado de un servicio:
$ cf service nombre-del-servicio
# "last operation: create in progress" → seguir esperando
# "last operation: create succeeded" → listo
# "last operation: create failed" → problema real

🏗️ Paso 5 — Generate Project

❌ El wizard se congela esperando confirmación (terminal colgada) ▼
✅ Resuelto en v1.1.0: El wizard siempre pasa --force al generar desde la UI. No hay prompts interactivos que puedan colgar el proceso.

Si estás en una versión anterior, actualizá con git pull && npm run build:all.

❌ "Permission denied" al generar el proyecto (Windows) ▼

Windows bloquea archivos que están siendo usados por otro proceso. Esto puede pasar si el editor tiene archivos del proyecto abiertos.

  • Cerrar VS Code u otros editores que tengan abierta la carpeta del proyecto
  • Usar un directorio de salida diferente (--output ./mi-app-nueva)
  • Correr PowerShell como Administrador si el problema persiste
❌ El nombre del proyecto tiene espacios o caracteres especiales ▼

Los nombres de proyecto deben cumplir restricciones de CF y npm: solo letras, números y guiones.

⚠ Restricciones de nombre: Solo a-z, 0-9 y -. Sin espacios, sin mayúsculas al inicio, sin guiones bajos, sin caracteres especiales.

✅ Válido: my-btp-app, sales-tool-v2

❌ Inválido: My App, sales_tool, app@2024

🚀 Paso 6 — Deploy

❌ VError: html5-repo-credentials: Missing required property: grant_type ▼
✅ Auto-reparado en v1.1.0 (Fix 4) La causa era usar el plan app-host del HTML5 App Repository para el AppRouter. Necesita app-runtime. El wizard lo detecta y corrige automáticamente antes del build.

Si el error persiste, verificá que estás usando la versión más reciente.

❌ mbt build falla con errores de npm ▼
✅ Fix 3 (npm-ci → npm) aplicado automáticamente

Si aún así falla:

# Instalar dependencias manualmente en cada módulo:
$ cd mi-app/srv && npm install && cd ../..
$ cd mi-app/approuter && npm install && cd ../..

# Verificar MBT:
$ mbt --version
# Si no está: npm install -g mbt
❌ cf deploy falla con "service binding error" ▼

El mta.yaml referencia un servicio CF que no existe o tiene un nombre diferente.

# Ver servicios disponibles:
$ cf services

# Los nombres en mta.yaml deben coincidir exactamente
# Verificar en mta.yaml → sección resources → name
❌ App queda en estado crashed después del deploy ▼ 
# Ver logs del crash:
$ cf logs mi-app-approuter --recent
$ cf logs mi-app-srv --recent

# Causas comunes:
# - Service binding faltante (ver "cf env mi-app-approuter")
# - Error en xs-app.json del approuter
# - Dependencias no instaladas (package.json incompleto)
❌ Quota de disco/memoria excedida en Trial ▼

SAP BTP Trial tiene límites de memoria y disco para apps.

# Ver consumo de recursos:
$ cf apps

# Detener apps que no se usan:
$ cf stop app-que-no-uso

# O eliminar apps previas:
$ cf delete app-vieja
❓ ¿Dónde vive la app desplegada? No la veo en BAS Projects. ▼
BAS es el IDE — la app vive en Cloud Foundry.

Para encontrarla: BTP Cockpit → tu Subaccount → Cloud Foundry → Spaces → tu Space → Applications

O desde terminal:

$ cf apps
$ cf app mi-app-approuter
# La URL de la app aparece en el campo "routes"

Roadmap & Futuras Features

Lo que viene — features planeadas y la visión a largo plazo del producto.

🔮 Features en Roadmap

🤖 Asistente IA para Diagnóstico de Errores

Un LLM pequeño y especializado, entrenado exclusivamente con errores de SAP BTP, documentación de CF, CAP y SAPUI5. Cuando el wizard falla, el asistente analiza el error y sugiere la solución exacta — sin tener que googlear.

Arquitectura pensada:

  • Modelo base: Phi-3.5-mini o Llama-3.2-3B (3-7B params, corre en CPU)
  • Fine-tuning con LoRA sobre: docs SAP BTP, SAP Community, errores reportados por usuarios
  • Modo local via Ollama (sin internet, sin costo) para usuarios técnicos
  • Modo cloud via API (pay-per-use) para usuarios que prefieren comodidad
  • Los reportes de errores de usuarios → dataset de entrenamiento continuo (flywheel)
Planned — Q3 2026

🔁 Reset por paso con re-validación automática

Botón de reset en cada paso que no solo limpia el estado sino que re-valida el estado real del entorno (servicios CF existentes, sesiones activas, archivos generados) antes de permitir continuar.

Planned — v1.2.0

👥 Modo Equipo — Configuraciones compartidas

Compartir una configuración de workspace BTP entre múltiples desarrolladores del mismo equipo. Un dev hace el setup una vez; el resto importa la configuración y empieza directo en el Paso 5.

Planned — v1.3.0

📊 Dashboard de estado del entorno

Vista en tiempo real del estado de todos los servicios CF, apps desplegadas, quotas de Trial y alertas proactivas (ej: "tu Trial expira en 7 días").

Planned — v1.4.0

🏢 Soporte multi-subaccount

Gestionar múltiples subaccounts BTP desde una sola interfaz — útil para consultoras que manejan proyectos de varios clientes simultáneamente.

Planned — v2.0.0
